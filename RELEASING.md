# Releasing

The release contract for the extension. Adapted from the Moonlight Peaks mods' release process
(guides 12-15 there), minus everything C#: there is no build, the archive is the five runtime files.

## Rules

- **`info.json` `version` is the only version.** The archive name, the Nexus file version and the
  Nexus page version all come from it. It moves only when publishing, never while developing, and
  `pack.ps1` never changes it.
- **First public version is 0.1.0** (Vortex shows versions below 1.0.0 as Beta). This is a
  deliberate exception to the Moonlight Peaks mods, which start at 1.0.0.
- **`info.json` `name` stays "Farm Together 2"** forever (Vortex keys on it), `gameId` stays 7911.
- **Page text comes from `NEXUS.md`.** `nexus-paste.md` is generated by `tools/nexus/render.js` and
  committed; never edit it by hand. (Moonlight Peaks treats the live page as the source; here the
  repo is, deliberately.)
- **One active Main file** on the Nexus page. An update replaces or archives the previous Main file.
- **Never move a published tag.** `v<version>` marks the exact commit that was packaged and uploaded.

## Checklist

1. **Prepare the release commit.** Bump `version` in `info.json`; add the `CHANGELOG.md` entry (for
   us) and the player-facing changelog line in `NEXUS.md`; update the description in `NEXUS.md` if
   the release changes what it says. If the live page was edited on Nexus since the last release,
   read it first and fold those edits into `NEXUS.md` (the nexus-publish skill's `description`
   mode does this). Run `node tools/nexus/render.js`. Commit all of it together.
2. **Run the fast gate** (README.md). All must pass on a clean tree.
3. **Package that clean commit:** `pack.ps1 -Json`. Record the archive path, version and SHA-256.
4. **Publish** with the `nexus-publish` skill (`.claude/skills/nexus-publish/SKILL.md`): `create` for
   the first release, `update` afterwards. It checks for an existing matching upload before
   uploading, sets the versions explicitly, and verifies the public page.
5. **After a confirmed upload:** `git tag -a v<version> -m "v<version>" <release commit>` and
   `git push origin v<version>`. If the tag already exists remotely, compare it with the release
   commit and stop on a mismatch; never force it.
6. **Record the receipt** in `nexus.json` (page ID, Main file ID, version, SHA-256, date) in a
   separate commit, and push.
7. **Discovery:** Vortex's manifest picks the extension up automatically, usually within about two
   hours (no review submission; Nexus may review afterwards). Treat discovery as pending until
   Farm Together 2 is seen in a clean Vortex's Games list; an uploaded file alone does not prove it.

## Recovery

- **Packaging failed:** nothing was written to `dist/` (the archive is built as a `.partial` and
  moved only after verification). Fix and re-run.
- **Upload interrupted:** resume by the IDs in `nexus.json` (or the page's edit URL). Check the Files
  tab for a Main file already at this version before uploading again; compare its size with the
  local archive.
- **Wrong file uploaded:** archive it on Nexus, upload the right one as Main, and note it in
  `CHANGELOG.md`. Do not reuse a version number for different bytes; bump the patch instead.
- **Tag pushed for the wrong commit:** leave it and release the next patch version.

## Owner-only steps

Signing in to Nexus in Chrome (including MFA or a CAPTCHA), connecting the Claude Chrome extension
if it is not connected, and GitHub authentication if `gh` is logged out. Everything else
(packaging, page text, upload, verification, tags) is agent-driven.
